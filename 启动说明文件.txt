MF Monitor System 启动说明

项目根目录：
d:\python_project\MF_Monitor_System

==================================================
一、平台启动方式
==================================================

推荐使用 HA 联调环境：

Windows PowerShell：
powershell -ExecutionPolicy Bypass -File .\scripts\start_p2_3_mysql_ha.ps1 -Env dev

说明：
这套会启动：
1. backend_api_1
2. backend_api_2
3. backend_worker
4. mysql
5. mysql_replica
6. mqtt_primary
7. mqtt_secondary
8. mqtt
9. nginx

停止平台：

Windows PowerShell：
powershell -ExecutionPolicy Bypass -File .\scripts\stop_p2_3_mysql_ha.ps1 -Env dev

==================================================
五、Windows 向 Jetson 推视频流
==================================================

说明：
RTSP 是推到 Jetson，不是推到 Windows 平台。

假设：
Jetson IP：192.168.31.210
视频文件：F:\graduation_dataset\DeFlow_Dataset\Data\cam2.mp4

Windows PowerShell：
ffmpeg -re -stream_loop -1 -i "F:\graduation_dataset\DeFlow_Dataset\Data\cam2.mp4" -an -c:v libx264 -preset veryfast -tune zerolatency -bf 0 -g 25 -keyint_min 25 -pix_fmt yuv420p -f rtsp -rtsp_transport tcp rtsp://192.168.31.210:8554/mf001

Jetson 上 mediamtx 日志应看到：
is publishing to path 'mf001'

==================================================

说明：

2. MQTT 发到 Windows 平台机器，所以用 Windows 局域网 IP

十二、平台联调检查顺序
==================================================

1. 先启动 Windows 平台 HA 环境
2. 确认 docker ps 里 mqtt / mysql / backend / nginx 都在运行
3. 启动 Jetson 上的 mediamtx
4. Windows 使用 ffmpeg 向 Jetson 推流
5. Jetson 运行 rtsp_probe
6. 确认 Jetson 日志里出现：
   [mqtt] connected ...
   [mqtt] device_status published
   [mqtt] classification published ...
7. 打开平台页面查看设备状态和分类结果

==================================================
十三、常见问题
==================================================

1. 如果 Jetson 报：
Connection refused
说明 Jetson 本机 mediamtx 没启动。

2. 如果 Jetson 报：
method DESCRIBE failed: 404 Not Found
说明 mediamtx 已启动，但 mf001 没有推流进来，需要重新执行 Windows ffmpeg 推流命令。

3. 如果 Jetson 报：
[mqtt] connect failed: Connection refused
说明 MQTT Broker 没启动，或者 Jetson 连错了地址。
HA 环境下应优先确认 Windows 平台容器已启动，并让 Jetson 连 Windows 的局域网 IP:1883。

4. 如果出现：
Missing reference picture
decode_slice_header error
通常是视频流刚接入时还没等到完整关键帧，只要后续推理和 MQTT 正常，一般不是主问题。
